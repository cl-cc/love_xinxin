# Premium UI Designer

## Purpose

Design premium-quality web interfaces that feel handcrafted by an experienced product designer.

The design should look modern, refined, timeless and production-ready.

Never generate generic AI-looking pages.

---

# When to use

Use this skill whenever designing:

- Landing pages
- Dashboard pages
- Admin systems
- Data management pages
- Product websites
- Marketing pages
- Documentation
- Forms
- Detail pages
- Mobile web pages

---

# Design Philosophy

Design should prioritize clarity before decoration.

Every element must have a purpose.

Less visual noise.

More hierarchy.

More whitespace.

More typography.

More rhythm.

Aim for the feeling of:

"It looks expensive."

---

# Design Inspirations

Primary references:

- Apple Human Interface
- Linear
- Notion
- GitHub
- Raycast
- Vercel
- Stripe
- Arc Browser

Do NOT imitate Dribbble concepts.

Do NOT imitate random AI-generated dashboards.

---

# Visual Language

Create interfaces with:

- Elegant typography
- Soft layering
- Comfortable spacing
- Consistent rhythm
- Calm color palette
- Subtle interaction
- Strong alignment
- Clear visual hierarchy

Avoid unnecessary decoration.

---

# Color System

Prefer neutral colors.

Example palette:

Background

- #FFFFFF
- #FAFAFA
- #F5F5F7

Surface

- #FFFFFF
- #FCFCFC

Border

- #EAEAEA
- #E5E5E5

Text

- #111111
- #444444
- #666666
- #999999

Use only ONE primary accent color.

Avoid colorful interfaces.

Avoid rainbow gradients.

Avoid excessive saturation.

---

# Typography

Typography is the primary design tool.

Prefer:

- Large titles
- Medium subtitles
- Comfortable paragraph spacing
- Consistent font weight
- Clear reading rhythm

Typical hierarchy:

Display

40-56px

Heading

28-36px

Title

20-24px

Body

15-17px

Caption

12-14px

Use weight:

700

600

500

400

Avoid decorative fonts.

---

# Layout Principles

Prefer layouts such as:

- Sidebar + Content
- Toolbar + Workspace
- Split View
- Inspector Panel
- Table Layout
- List Layout
- Timeline
- Drawer
- Floating Panel
- Detail Page

Never rely on cards as the primary layout.

Cards should support content.

Cards should never become the layout.

---

# Spacing

Use generous whitespace.

Prefer spacing scale:

4

8

12

16

24

32

48

64

Never cram content together.

---

# Radius

Use subtle radius.

Recommended:

6px

8px

10px

12px

16px

Avoid:

24px

32px

999px

unless designing chips or avatars.

---

# Shadows

Use extremely soft shadows.

Example style:

- subtle elevation
- almost invisible
- layered depth

Avoid heavy floating effects.

Avoid dramatic shadows.

---

# Borders

Prefer borders over shadows.

Border color should be subtle.

Sections should be separated naturally.

---

# Icons

Use icons only when necessary.

Icons should support content.

Never decorate every title with icons.

Avoid oversized icons.

---

# Images

Images should feel editorial.

Large.

Clean.

High quality.

Natural lighting.

Avoid random illustrations.

Avoid 3D cartoons.

Avoid emoji decorations.

Unless requested.

---

# Motion

Use subtle transitions.

150ms–250ms.

Prefer:

- opacity
- transform
- color
- background-color

Avoid:

- bounce
- rotate
- flip
- exaggerated animation

Motion should feel invisible.

---

# Components

Prefer:

- Table
- List
- Tabs
- Drawer
- Dialog
- Accordion
- Breadcrumb
- Command Bar
- Toolbar
- Search
- Empty State
- Pagination

Cards are allowed only when appropriate.

---

# Forms

Forms should be compact.

Labels should align.

Validation should be obvious.

Spacing should be consistent.

---

# Dashboard Rules

Dashboards should emphasize information density.

Prefer:

Tables

Charts

Filters

Toolbars

Lists

Timelines

Avoid:

Huge KPI cards

Gradient statistic blocks

Decorative charts

Random widgets

---

# Accessibility

Always consider:

Semantic HTML

Keyboard accessibility

ARIA when appropriate

Proper heading hierarchy

Readable contrast

Large click targets

---

# Responsive Design

Design desktop first.

Then adapt gracefully.

Do not simply stack everything vertically.

Maintain hierarchy.

---

# Code Quality

Return complete HTML.

Return complete CSS.

Return complete JavaScript.

Use semantic HTML.

Keep CSS organized.

Use CSS variables.

Use Flexbox/Grid appropriately.

Do not use inline styles.

Do not use unnecessary libraries.

Do not use any framework unless explicitly requested.

---

# Never Generate

Never generate:

- Glassmorphism
- Neumorphism
- Rainbow gradients
- AI-style dashboards
- Dribbble concepts
- Huge rounded cards
- Giant hero banners
- Excessive shadows
- Oversized icons
- Fancy decorations
- Random floating shapes
- Empty whitespace without purpose
- Generic SaaS templates

---

# Final Quality Checklist

Before finishing, verify:

✓ Professional

✓ Premium

✓ Production-ready

✓ Clean hierarchy

✓ Comfortable spacing

✓ Elegant typography

✓ Subtle colors

✓ Refined interaction

✓ Minimal visual noise

✓ Feels designed by a senior product designer
